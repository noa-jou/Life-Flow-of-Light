# 歲月流明 — 使用指南

[English](UserGuide.md) · [專案介紹](../README.zh-TW.md) · [專案結構與技術簡介](StructureIntro.zh-TW.md)

這份指南帶你在自己的電腦上設定歲月流明，並實際操作本機展示。

以下範例以作者的開發環境為示範：Chromebook Linux 開發環境中的 Debian Linux。這是一個參考環境，不代表你必須使用相同的電腦或作業系統。

如果你使用 Windows、macOS 或其他 Linux 發行版，可以透過這些步驟了解需要完成哪些工作，再依自己的環境調整安裝指令、終端機設定與檔案路徑。

本指南無法為每一種作業系統分別示範完整操作，也未在所有平台上驗證以下範例。

我們會先準備工具、下載專案，再安裝及啟動前後端，最後查看燈光歷史，並練習發送一段摩斯訊息。

如果你想了解專案各部分如何組成，可以閱讀[專案結構與技術簡介](StructureIntro.zh-TW.md)。不需要先讀懂架構，也可以跟著這份指南操作。

## 1. 開始前的準備

如果要直接跟著 Debian 範例操作，你需要：

- 一個可以使用 Bash 終端機的 Debian Linux 環境。
- 使用 `sudo` 安裝系統套件的權限。

如果使用 Chromebook，請先啟用其 Linux 開發環境。

無論使用哪一種作業系統，你都需要：

- 瀏覽器與合適的終端機。
- Node.js 24.x 與 npm。
- 如果使用 `git clone` 下載專案，需要安裝 Git。
- 網路連線，用來下載專案與依賴套件。
- 如果儲存庫尚未公開，則需要對應的存取權限。

接下來會示範如何在 Debian 上準備這些工具。其他作業系統的使用者，請採用適合自己環境的安裝方式。

展示會在本機執行。不需要實體燈泡、感測器、雲端帳號，也不需要另外啟動資料庫伺服器。

請只使用一個瀏覽器分頁操作展示。多個分頁或用戶端同時操作，可能發送互相衝突的燈光活動。

### 如何閱讀與調整指令

只需要複製程式碼區塊中的指令，不要複製 `noa@penguin:~$` 之類的終端機提示文字。

按照順序執行。如果某個指令失敗，請先查看錯誤訊息，並確認指令是否適用於你的環境，再繼續下一步。

範例使用 Bash：

- `~` 代表你的家目錄。
- `cd` 用來切換目前目錄。
- `pwd` 顯示目前所在的目錄。
- `ls` 列出目錄中的檔案。

本指南假設專案位於：

`~/Life-Flow-of-Light`

如果你下載到其他地方，請相應調整路徑。

`apt`、`sudo` 與 `source ~/.bashrc` 等指令與示範環境有關，不應假設它們能原封不動地套用到不同的終端機環境或作業系統。

重點是在自己的電腦上完成相同的設定工作，實際使用的指令可以不同。

## 2. 安裝基本系統工具

開啟終端機，執行：

```bash
sudo apt update
sudo apt install -y git curl ca-certificates
```

`apt update` 會更新可安裝套件的清單。第二個指令會安裝：

| 工具 | 為什麼需要 |
| --- | --- |
| Git | 下載儲存庫，以及處理日後的程式更新。 |
| curl | 下載 Node 版本管理工具，以及檢查後端連線。 |
| ca-certificates | 協助驗證安全的 HTTPS 連線。 |

如果 `sudo` 要求輸入密碼，輸入時終端機可能不會顯示任何字元，這是正常的。

## 3. 準備 Node.js 24

前端與後端都需要 Node.js `24.x`。

如果已經安裝 Node.js 與 npm，先檢查版本：

```bash
node -v
npm -v
```

如果 Node.js 顯示 `v24.x.x`，而且 npm 可以使用，就可以跳過本節剩餘步驟。

如果是全新的 Debian 環境，以下示範使用 nvm 安裝 Node.js。

### 安裝 nvm

如果已經安裝 nvm，可以跳過這個安裝程式。

```bash
curl -fsSL https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.8/install.sh | bash
source ~/.bashrc
nvm --version
```

第一個指令會從 nvm 官方儲存庫下載並執行安裝程式。

`source ~/.bashrc` 會將更新後的 Bash 設定載入目前的終端機。

如果仍找不到 `nvm`，請關閉終端機，重新開啟後執行：

```bash
nvm --version
```

詳細安裝說明請參閱 [nvm 官方文件](https://github.com/nvm-sh/nvm#installing-and-updating)。

### 安裝 Node.js 並設定預設版本

```bash
nvm install 24
nvm alias default 24
node -v
npm -v
```

這些指令會：

1. 安裝 Node.js 24，並在目前終端機選用它。
2. 將 Node.js 24 設為新終端機載入 nvm 後的預設版本。
3. 顯示安裝好的 Node.js 與 npm 版本。

`node -v` 應顯示以 `v24.` 開頭的版本。

Node.js 已包含 npm，不需要另外安裝 npm。

對新的開發環境而言，設定預設版本會比較方便。如果你原本還有其他 Node.js 專案，可以保留既有的預設版本，改成在操作本專案時使用 `nvm use 24`。

只要目前已使用正確版本，就不需要在每個指令前重新選擇。

本指南中的 npm 指令不需要加上 `sudo`。

## 4. 下載專案

如果你已經下載完整儲存庫，可以跳過 clone 指令，直接進入現有的專案資料夾。

首次下載時，請開啟專案的 GitHub 頁面，從 **Code** 按鈕複製 HTTPS 網址。

將以下範例的 `YOUR_GITHUB_OWNER` 換成實際的儲存庫擁有者：

```bash
cd ~
git clone https://github.com/YOUR_GITHUB_OWNER/Life-Flow-of-Light.git
cd ~/Life-Flow-of-Light
```

上面的網址含有待替換文字，並非實際儲存庫網址。

`git clone` 用於首次下載；`git pull` 則是在已有的儲存庫副本中取得更新。

檢查專案根目錄：

```bash
pwd
ls
```

你應該看到：

```text
backend  docs  frontend  README.md  README.zh-TW.md
```

下載儲存庫取得的是原始碼，不會一併取得作者電腦上的本機資料庫或已安裝套件。

## 5. 安裝後端依賴套件

執行：

```bash
cd ~/Life-Flow-of-Light/backend
npm ci
```

`npm ci` 會按照 `package-lock.json` 記錄的版本安裝依賴套件。

不需要執行 `npm init`，也不需要逐一安裝 Express、TypeScript 等套件。專案已經宣告所需的依賴。

等安裝成功完成後，再繼續下一步。

### 檢查後端

```bash
npm run typecheck
npm test
npm run build
```

這些指令依序檢查應用程式型別、執行自動化測試，以及編譯後端。

測試會準備自己的測試環境，不需要先啟動伺服器或產生示範資料。

測試數量可能隨專案發展而改變。請確認沒有測試失敗，而且每個指令都成功完成。

## 6. 選擇資料庫的起始方式

後端的資料庫模組第一次執行時，會初始化本機資料庫。

資料庫檔案位於：

`backend/data/life-flow-of-light.sqlite`

你不需要手動建立資料表，也不需要另外安裝 SQLite 伺服器。

### 初次體驗建議：使用示範資料

仍然在 `backend/` 中，執行：

```bash
npm run seed
```

示範資料會建立：

- 三顆燈泡：A、B、C。
- 三十一筆亮燈時段。
- 執行指令前的三個完整本機日曆日紀錄。
- 第三天晚上，臥室中的 HELP 摩斯訊號。

日期依照執行 seed 時電腦的本機時區計算。

這樣啟動介面後，就有歷史資料可以查看。

Seed 要求應用程式的資料表為空；如果已有紀錄，就會拒絕覆寫。

新的展示資料庫執行一次即可。它不會每天自動更新示範日期，也不需要每次啟動專案都重新執行。

### 另一種方式：從空資料庫開始

跳過 `npm run seed`。

後端啟動時會初始化空資料庫，之後你可以透過介面新增並安裝燈泡。

History 面板一開始不會有已儲存的燈光活動。

如果 seed 因為已有紀錄而拒絕執行，你仍可繼續使用那些紀錄。不要只是為了繼續閱讀這份指南，就刪除自己的資料庫。

## 7. 在終端機 A 啟動後端

在 `backend/` 中執行：

```bash
npm run dev
```

後端預期會在以下網址接收請求：

`http://127.0.0.1:3000`

讓這個終端機保持執行。我們將它稱為終端機 A。

終端機持續被佔用是正常的，表示伺服器正在執行，直到你主動停止。

這個網址是後端 API，不是前端應用程式頁面。

## 8. 在終端機 B 安裝並啟動前端

開啟第二個終端機。

先檢查後端是否有回應：

```bash
curl http://127.0.0.1:3000/health
```

預期回應：

```json
{"status":"ok","database":"connected"}
```

這表示後端可以連線，而且能夠查詢資料庫。

接著安裝前端依賴套件：

```bash
cd ~/Life-Flow-of-Light/frontend
npm ci
```

檢查前端：

```bash
npm run build
npm run lint
```

然後啟動前端開發伺服器：

```bash
npm run dev
```

也讓終端機 B 保持執行。

在瀏覽器開啟 Vite 顯示的 **Local** 網址，通常是：

`http://localhost:5173`

如果終端機顯示不同網址，請使用實際顯示的網址。

前端透過 Vite 開發代理，將 `/api` 請求轉送至後端。因此兩個終端機都必須保持執行。

不需要手動開啟 `index.html`。

## 9. 認識操作介面

頁面依序包含四個面板：

| 面板 | 可以做什麼 |
| --- | --- |
| 燈泡（Bulbs） | 管理虛擬燈泡及其安裝位置。 |
| 屋子（House） | 操作模擬燈光。 |
| 歷史（History） | 查看近期活動與已儲存的亮燈時段。 |
| 摩斯（Morse） | 跟著課程練習，並搜尋已記錄的摩斯訊息。 |

使用語言切換控制，可以切換英文與繁體中文。

面板可以收合或展開。最多兩個面板共同使用可用空間；只有一個面板展開時，可以使用較寬的版面。

展開另一個面板，可能讓原本的面板收合。如果關閉最後一個展開的面板，請依照對話框選擇接下來要開啟的面板。

部分欄位與控制項會依照面板寬度改變呈現方式。

### 哪些操作會停止模擬燈光

- 重新載入頁面會將模擬燈光重設為關閉。
- 新增、安裝、卸載或刪除燈泡會重新載入頁面。
- 收合 House 會停止當時正在亮起的燈光。
- House 收合後，可以使用按住發光的按鈕，產生新的訊號。

重新載入頁面後，資料庫中已儲存的歷史仍然保留；暫時性的即時活動條則會重設。

錄製摩斯訊息時，請避免重新載入頁面或管理燈泡。

## 10. 試試一般燈光操作

如果已載入示範資料，三個房間位置都已安裝燈泡。

如果沒有：

1. 展開 **Bulbs**。
2. 新增一顆燈泡。
3. 如有需要，改成容易辨認的名稱。
4. 選擇一個可用位置。
5. 如果想控制全部三個房間，再為其他位置重複操作。

可用位置為客廳、臥室及浴室。每個位置只能安裝一顆燈泡。

接著：

1. 展開 **House**。
2. 使用房間的燈光控制開燈。
3. 讓燈保持亮起數秒。
4. 關燈。
5. 在 **History** 觀察近期活動顯示。

未安裝燈泡的位置無法發送燈光活動。

### 燈泡管理規則

- 自訂名稱不可為空，且最多二十個 Unicode 碼位。
- 序號不可變更。
- 卸載前，先關燈，並等待後端確認燈泡已停止活動。
- 卸載只是移除安裝位置，不會刪除歷史紀錄。
- 只有未安裝且沒有亮燈歷史的燈泡可以刪除。

如果剛關燈就卸載而遭到拒絕，請稍等一下，再試一次。

## 11. 查看 History 歷史紀錄

展開 **History**。

使用 **From／起始日期** 與 **To／結束日期** 選擇日期範圍。範圍包含選取的起始日與結束日。

有效日期範圍變更時，History 會載入紀錄。

查看示範資料時，請選擇執行 seed 當天之前的三天。如果過了幾天才回來查看，需要將日期調回當時產生資料的日期。

使用 **By／分組方式** 改變排列：

| 分組 | 結果 |
| --- | --- |
| Day／日期 | 每個日期一張圖，顯示三個位置。 |
| Position／位置 | 每個位置一張圖，顯示選取的日期。 |

你也可以：

- 反轉日期排列順序。
- 放大時間軸，查看較短的時段。
- 在放大後的圖表中水平捲動。
- 將游標移到紀錄長條上，查看燈泡、位置與時間。

改變分組只會改變呈現方式，不會修改已儲存的紀錄。

### 即時活動與已儲存歷史的差別

即時活動條顯示前端近期活動，每格代表一秒：

- 金色：該秒中的某個時刻曾觀察到亮燈。
- 淡藍色：該秒未觀察到亮燈。

一格金色不代表整整亮了一秒，因此不要將金色格數當成精確計時器。

歷史圖表顯示從資料庫取得的紀錄。產生新活動後，若要重新查詢，可以變更日期範圍，再切回想查看的範圍。

空白圖表表示該次選取沒有回傳紀錄。這與請求失敗不同；請求失敗時應顯示錯誤訊息。

## 12. 找出示範資料中的摩斯訊息

如果已執行 seed：

1. 展開 **Morse**。
2. 設定起始與結束日期時間，涵蓋第三個示範日的晚上。
3. 按下 **搜尋**。
4. 在結果中尋找來自臥室紀錄的 HELP。

初次搜尋時，可以直接涵蓋全部三個示範日，並將結束時間設為其後一天早上。

搜尋涵蓋三個支援的位置，結果會標示偵測到的訊息來自哪裡。

Morse 會在按下 搜尋 時驗證時間範圍。起始時間必須早於結束時間。

如果找不到訊息，請對照實際執行 seed 的日期，重新檢查搜尋範圍。

## 13. 自己發送摩斯訊息

Morse 面板包含四個課程：

| 課程 | 練習內容 |
| --- | --- |
| 1 | 按照詳細步驟發送 SOS。 |
| 2 | 使用 A–Z 對照表練習字母。 |
| 3 | 發送 I CAN USE MORSE CODE。 |
| 4 | 自行組成一段訊息。 |

建議先從 Lesson 1 開始。

### 準備控制按鈕

1. 確認選定位置已安裝燈泡。
2. 收合 **House**，顯示按住發光的按鈕。
3. 開啟 **Morse**，選擇 Lesson 1。
4. 整段訊息使用同一個位置及同一顆燈泡。

按住按鈕時會發送燈光活動，放開後停止訊號。

### 跟著時間節奏操作

| 動作 | 目標時間 |
| --- | --- |
| 點：按住 | 2 秒 |
| 劃：按住 | 6 秒 |
| 同一字母內，訊號之間放開 | 2 秒 |
| 字母之間放開 | 6 秒 |
| 單字之間放開 | 14 秒 |
| 最後一次放開後，搜尋前等待 | 至少 18 秒 |

每個分隔位置只使用一種適當的間隔，不要把間隔相加。

例如，兩個字母之間總共放開六秒，不是先放開兩秒，再額外放開六秒。

### 搜尋剛才的嘗試

1. 完成最後一個訊號，放開按鈕。
2. 等待至少十八秒。
3. 將搜尋起始時間設在第一個訊號之前。
4. 將結束時間設在訊息之後，建議使用等待結束後的目前時間。
5. 按下 **搜尋**。
6. 對照結果的時間與位置，確認哪一筆是剛才的嘗試。

繼續練習後，再次搜尋前也要更新結束時間。

解碼器目前支援英文字母 A–Z 與空格，不要預期數字或標點符號能正常解讀。

介面提供操作節奏指引，但如果按住或放開的時間超出接受範圍，手動訊號仍可能被誤讀。

例如，O 是同一個字母內的三個劃，劃之間使用短間隔。如果在三個劃之間停得太久，可能會被解讀成 TTT。

這是訊號解讀的展示。發送 SOS 或 HELP 不會聯絡任何人，也不會啟動緊急救援服務。

## 14. 停止與下次啟動

停止專案時：

1. 完成目前的訊號，關閉模擬燈光。
2. 在終端機 B 按下 `Ctrl+C`。
3. 在終端機 A 按下 `Ctrl+C`。

停止伺服器不會刪除資料庫。

### 下次重新啟動

終端機 A：

```bash
cd ~/Life-Flow-of-Light/backend
npm run dev
```

終端機 B：

```bash
cd ~/Life-Flow-of-Light/frontend
npm run dev
```

開啟 Vite 顯示的 Local 網址。

只要目前環境已使用正確版本，就不需要重新安裝依賴套件、重新選擇 Node.js，或重新執行 seed。

只有在刻意重新安裝依賴，或更新後的依賴檔案有變更時，才需要再次執行 `npm ci`。

### 備份紀錄

停止後端，確認沒有其他程序使用資料庫，再將整個 `backend/data/` 資料夾複製到備份位置。

原始碼下載與資料庫備份的用途不同。重新下載儲存庫，不會還原你已儲存的燈光紀錄。

## 15. 選用：執行編譯後的後端

前面的主要流程使用開發模式。

如果想改成執行編譯後的後端，請先使用 `Ctrl+C` 停止後端開發伺服器，再執行：

```bash
cd ~/Life-Flow-of-Light/backend
npm run build
npm start
```

`npm start` 執行的是產生出來的 JavaScript，不會先替原始碼進行編譯。

請將 `schema.sql` 保留在 `backend/`，並從該目錄執行這些指令。

終端機 B 可以繼續使用前端開發伺服器。

前端的 `npm run preview` 用來預覽建置後的前端資源，不會啟動後端，也不是完整的部署流程。

## 16. 常見問題

| 問題 | 可以檢查什麼 |
| --- | --- |
| `nvm: command not found` | 執行 `source ~/.bashrc`，或在安裝後重新開啟終端機。 |
| Node.js 不是版本 24 | 使用 `node -v` 檢查。如果使用 nvm，在目前終端機執行 `nvm use 24`。 |
| 新終端機總是選用其他 Node.js 版本 | 如果希望預設使用版本 24，執行 `nvm alias default 24`，並確認終端機有載入 nvm。 |
| npm 找不到 `package.json` | 使用 `pwd` 確認位置，先進入 `backend/` 或 `frontend/` 再執行 npm 指令。 |
| `npm ci` 表示套件檔案不一致 | 確認 `package.json` 與 `package-lock.json` 來自同一個專案版本。 |
| 下載失敗 | 檢查網路連線及錯誤訊息，再嘗試下載。 |
| 健康檢查無法連線 | 確認終端機 A 的後端仍在執行。 |
| 連接埠 3000 已被使用 | 檢查是否有另一個後端終端機，停止重複的伺服器。 |
| 瀏覽器無法開啟前端 | 使用 Vite 顯示的 Local 網址，並保持終端機 B 執行。 |
| 頁面能開啟，但 API 請求失敗 | 檢查後端終端機，並再次執行健康檢查。 |
| 房間按鈕無法使用 | 在該位置安裝燈泡。 |
| 卸載遭拒絕 | 關燈後等待後端確認停止活動，再試一次。 |
| 刪除燈泡遭拒絕 | 燈泡必須未安裝，而且沒有歷史時段。 |
| Seed 拒絕執行 | 既有紀錄受到保護。繼續使用它們，或使用另外準備的空資料庫。 |
| History 沒有紀錄 | 檢查選取日期，尤其是當初產生示範資料的日期。 |
| Morse 找不到訊息 | 檢查搜尋範圍、訊號節奏及最後等待時間，並更新結束時間。 |
| Morse 出現非預期訊息 | 檢查結果時間，並同時檢視按住時間及放開間隔。 |
| 查詢表示紀錄過多 | 縮短查詢時間範圍。 |
| `npm start` 找不到 `dist/server.js` | 先在 `backend/` 成功執行 `npm run build`。 |

如果想進一步了解背後原理，請閱讀[專案結構與技術簡介](StructureIntro.zh-TW.md)。
